4Fallback and fault ownership

Host guarantees: failure isolation; unmount removes registrations and injected styles.
Accepted costs: same-realm code can reach globals; style rewrites can be bypassed; manifest validation is not a security boundary.

5Permissions

Pure display slots ride on renderer.extension. Side effects are declared against the vocabulary and paired with a permission.

6Finalization record

  • SDK slot names are final: userAction / assistantAction / entryExtra; each slot page links here instead of restating this contract
  • Registration uses one discriminated union: { slot: "userAction" | "assistantAction" | "entryExtra" | "toolCard", ... }; a toolCard entry must carry a toolName that matches contributes.agentTools[].name in the manifest
  • Each side position (userAction / assistantAction) shows at most three items; the fourth and later move into the host's "..." overflow menu. A collapsed entryExtra block is 320px tall and a 600px expanded block scrolls internally
  • Composer trigger characters are fixed at @ / # / /; a draft holds at most eight tokens; a running tool-card pushes on a 500ms coalescing tick (state transitions push immediately)
  • ui.ask keeps its name: it shares a name with, but is not, the agent-side boolean confirmation. The disambiguation wording in render/ask is authoritative
  • The SDK and host are implemented (seven slots plus the self-dialog guidance entry; dispatch vocabulary plugin.call / composer.insertText / composer.acceptTriggerItem); see examples/plugins/ui-slots-lab for a sample and apps/desktop/test/plugin-*.test.mjs for the contract tests
