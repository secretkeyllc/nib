Confirmation card - Requirements

Ask the user one question: confirm, choose between two, or acknowledge. The interface is ui.ask (formerly the ui.confirm semantics; renamed to disambiguate). The return is always an object, the card shell belongs to the host, and the buttons are configured.

status: draft - issue #545 - #561 - outbound layering: optional H

Scope Settled

  • One renderer interface: ui.ask - the plugin initiates a confirmation, choice, or acknowledgement and waits for the user to press one button.
  • The card shell belongs to the host; content and buttons come from arguments; the return is always { choice, reason? }.
  • Not covered: self-managed dialogs and floating layers (ui/self-dialog/), the host permission approval card, and the agent-side boolean confirmation.

Contract shape Decided

// call (inside the plugin renderer)
const result = await pi.ui.ask({
  title: "分支清理 · 确认删除",
  description: "将删除 feat/528 等 3 个分支",
  actions: [
    { id: "cancel",  label: "取消",     variant: "ghost" },
    { id: "delete",  label: "全部删除", variant: "primary" },
  ],
})

// returns: always an object; never a string-or-object union
{ choice: "delete" }
{ choice: "cancel",  reason: "plugin-unloaded" }

Outbound layerOptional H (the same tier as toast, clipboard.write, host.open, readDraft, and list / remove)
Two-state returns are forbidden (decided). The old shape returned a string sometimes and an object other times, forcing callers to write two branches. Everything is an object now: choice is always present and reason is optional. Unload returns an object too and no longer throws a special value.
Fixed card shell, configured buttons (decided). The shell and button styling belong to the host; a plugin supplies only the title, the description, and the button list. No plugin code runs inside the card - layout and click dispatch are the host's.

Explicit non-goals Settled

  • It does not take over the host permission approval card. That card is a security decision surface that belongs only to the host; the old takeover slot is gone. ui.ask never enters the permission queue's decision path.
  • It accepts no components and allows no custom drawing. Nothing in the card is rendered by a plugin; the content is the fixed title + description fields only.
  • String-or-object returns are forbidden. Always { choice, reason? }.
  • No layer mechanism. The confirmation card is not registered and takes no part in layer arbitration; for a free-form UI use ui/self-dialog/.
  • Same name, different thing - disambiguation is mandatory. The agent side also has a "confirmation", but it returns a boolean (allow / deny) and travels the tool-approval path, whereas this interface asks the user a question from the renderer and returns { choice, reason? }. This interface is named ui.ask and is no longer called confirm. The two must never share a return shape.
Disambiguation in one sentence. Asking the user which button to press -> ui.ask (this folder). Whether to let a tool run -> the agent-side boolean confirmation (the host approval card). The name collision is a historical accident; the rename removes the ambiguity and is not an alias.
