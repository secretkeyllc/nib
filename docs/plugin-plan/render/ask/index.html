Confirmation card - Index

The interface for asking the user one question: ui.ask. Fixed card shell, configured buttons, and the return is always { choice, reason? }. This is a render interface, not a UI slot - it claims no position and never enters the component tree.

status: draft - issue #545 - #561 - the former ui.confirm semantics, renamed to disambiguate

Why there is no demo

Interface-only, so the demo is omitted. This folder pins the contract only (input, return, boundaries); there is no mountable UI slot. For what the card looks like, see the confirmation-card scene in ui/layers/demo.html (the former ui.confirm shape - the look is unchanged; only the return value and the name changed).

Summary

  • The name is ui.ask (settled; formerly ui.confirm) - it shares a name with, but is not, the agent-side boolean confirmation. The rename removes the ambiguity.
  • The return is always an object { choice, reason? }; a sometimes-string, sometimes-object return is forbidden.
  • On unload the result is reason: "plugin-unloaded"; pending waits settle too and nothing is left hanging.
  • The card shell belongs to the host; buttons are configured (label, variant). No plugin code runs inside the card.
  • It does not take over the host's permission approval card - that card is a security decision surface and always belongs to the host.
  • In the outbound layering it is optional H.
