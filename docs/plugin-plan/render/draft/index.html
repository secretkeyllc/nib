Draft read/write - Index

Three methods for the composer draft: composer.readDraft / composer.replaceDraft / composer.insertText. Reading is a snapshot; writing has two paths - insertion is the primary path and whole replacement is restricted. This is a render interface, not a UI slot.

status: draft - issue #545 - #561 - draft changes are pushed through rendererData draft; do not poll

Why there is no demo

Interface-only, so the demo is omitted. This folder pins the call contract; there is no mountable UI slot. For the composer and its tokens, see ui/composer/demo.html; the draft methods appear there in prose under scenarios 5 / 7 / 4, and no separate UI demo page is made.

Summary

  • readDraft -> { text, marks[] } (carrying a generation, used to reconcile replacement).
  • insertText is the primary path: insert a run of text at the caret; any plugin can use it at any time.
  • replaceDraft is restricted by three gates: generation reconciliation (CAS expectedGeneration), the composer must not be focused, and remote origins are forbidden.
  • The host pushes draft changes to the plugin (rendererData draft); a plugin must not poll.
  • Outbound layering: insertText is core H; readDraft is optional H; remote replaceDraft is rejected.

Open questions

The field name for marks (keep the old tokens or settle on marks) and the generation overflow policy are open - see "Open questions" in data-flow.html.
