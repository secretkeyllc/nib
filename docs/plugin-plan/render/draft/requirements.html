Draft read/write - Requirements

Reading and writing the composer draft: composer.readDraft / composer.replaceDraft / composer.insertText. Insertion is the primary path, whole replacement has three gates, and draft changes arrive by push, never by polling.

status: draft - issue #545 - #561 - insertText is core H - readDraft is optional H - remote replace is rejected

Scope Settled

  • Three methods covering the composer's draft text and tokens:
    • composer.readDraft - read a snapshot
    • composer.insertText - insert a run of text at the caret (primary path)
    • composer.replaceDraft - replace the whole draft (restricted)
  • The host pushes draft changes (rendererData draft); plugins do not poll.
  • Not covered: the three attachment actions (render/attachments/), the composer UI slot (ui/composer/), and pre-send rewriting (runtime/before-send/).

Contract shape Decided

Read a snapshot

// request: no arguments
composer.readDraft()

// returns
{
  text,                 // current composer text
  marks: [ … ],         // token list, in order of appearance
  generation            // draft generation; increments on every draft change, used by replaceDraft for reconciliation
}

Insert (primary path)

// request: insert a run of plain text at the caret
composer.insertText({ text: "请对照 docs/spec/00-baseline.md" })

// returns
{ ok: true, generation }

Whole replacement (restricted)

// request
composer.replaceDraft({
  expectedGeneration,   // must equal the current generation; a mismatch rejects the whole call (CAS)
  text,
  marks?
})

// returns
{ ok: true, generation }
// or an error: generation mismatch / composer focused / remote origin -> whole call rejected

The three replace gates(1) CAS expectedGeneration; (2) writable only when the composer is not focused; (3) remote origins are forbidden
insert's roleThe primary path - remote results, templates, and snippets all go through insertion
DeliveryDraft changes are pushed through rendererData draft; do not poll
The three replace gates (decided).Whole replacement would overwrite what the user is typing, so all three must hold at once: the generation matches, the composer is not focused, and the caller is not a remote callback. If any gate fails, the entire call is rejected and nothing is partially written.
Remote origins cannot replace (decided).A "remote origin" is any asynchronous result: a plugin-forwarding answer, a network callback, data arriving late from a timer. Those cases may only use insertText, never whole replacement - the user may be typing, and a late whole-block replacement would eat their text.
Push, never poll (decided).Whenever the draft changes (the user types, edits, or a plugin writes), the host pushes a new snapshot through rendererData draft. A plugin subscribes; it must not read on a timer.

Explicit non-goals Settled

  • Remote origins may not call replaceDraft.Async callbacks, network responses, and late timer data may only insert.
  • No polling interface.Draft changes arrive by push; adding polling would create a second source.
  • No whole replacement while the composer is focused.The user is typing; replacing would eat their text.
  • No silent overwrite.A generation mismatch rejects the whole call; no partial writes and no forced overwrite.
  • Never touch the host's own tokens (for example the anchor used when editing a past message): if replace would drop one, the whole call is rejected.
  • No attachment read/write.That belongs to render/attachments/; this folder covers draft text and tokens only.
