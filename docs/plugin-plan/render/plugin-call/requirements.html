Plugin forwarding - Requirements

A renderer component fetching its own plugin's private data: dispatch("plugin.call"). One question, one JSON answer, with five constraints - a method allowlist, a payload cap, a rate limit, a timeout, and a circuit breaker - and pluginId injected by the host.

status: draft - issue #545 - #561 - outbound layering: core P

Scope Settled

  • One renderer action: dispatch("plugin.call") - a slot component asks its own plugin for data.
  • The chain is fixed: dispatch -> validate the declaration -> forward across processes -> the plugin answers -> JSON comes back.
  • Not covered: cross-plugin calls (forbidden), streaming or subscriptions (forbidden), and host capability calls (those are other outbound verbs).

  args:   { query: "refund policy" }
})
// pluginId never appears here - the host injects it and it cannot be self-supplied

// (2) cross-process payload (assembled by the host)
IPC plugin/renderer/call
  { pluginId, method, args }

// (3) plugin-side response
onRendererCall(method, args) → JSON value

AnswerJSON - not a stream, not a function, no circular references
No streaming (decided).One question yields one answer and the return must be JSON-serializable. For ongoing data, call repeatedly or subscribe to the host's push channel - this interface is not a stream.
pluginId is injected by the host (decided).A component may write only method and args; the host fills in "who this is" in the cross-process payload. That closes off impersonating another plugin and bypassing the ownership gate.

Scenarios Typical usage

#scenario
1A knowledge-base slot component searches entries in its own plugin index and gets a list back

Explicit non-goals Settled

  • No streaming.It is not a subscription or an event source; one question, one JSON answer.
  • No cross-plugin calls.The host injects pluginId, so a plugin can only call itself; impersonation is rejected.
  • No undeclared methods.Anything outside the allowlist is NO_HANDLER.
  • Side effects beyond fetching data do not go here.Writing the draft, adding attachments, copying, and opening links each have their own outbound verb; none opens a back door through plugin.call.
  • Failures are never silent. Timeouts, over-limit calls, and the circuit breaker all return a code; nothing pretends to succeed.
  • No unlimited retries on consecutive failures. The breaker trips PLUGIN_CALL_DISABLED and forwarding takes a break.
