Attachments - Requirements

Three attachment-area actions: attachments.add / attachments.list / attachments.remove. They accept content or a token only; the host moves it into a staging area; visibility and operations are limited to the plugin's own entries.

status: draft - issue #545 - #561 - S1 red line: no path / file:// / URL references

Scope Settled

  • Three actions covering the composer attachment area:
    • attachments.add - add an attachment (content or a token; the host stages it)
    • attachments.list - list what this plugin added
    • attachments.remove - remove what this plugin added
  • Not covered: draft text (render/draft/), the attachment UI slot (ui/composer/), and how content is fetched at send time (implementation detail).

Contract shape Decided

// (1) add - accepts only content or a token
attachments.add({
  name: "chart.png",          // display name; the extension is required
  mimeType: "image/png",       // decides between an image thumbnail and a file chip
  content | token               // either the content itself or a token that fetches it
})
// → { id }
// rejected: path / file:// / URL reference, or a name without an extension

// (2) list - only entries this plugin added
attachments.list()
// → [{ id, name, mimeType, size, … }]

// (3) remove - only entries this plugin added
attachments.remove(id)
// → { ok: true }
// rejected: the id does not exist, or that entry was not added by this plugin

Content custodyThe host moves it into the staging area; once handed over, the plugin holds no address
list visibilityLists only its own - entries added by the user or by other plugins are invisible
remove boundaryTouches only its own - anything belonging to others or to the user is refused
S1 red line (decided).No path / file:// / URL references. A plugin may not hand over a local path or a network address for the host to read, nor stuff a bare path into an attachment. Content reaches the staging area by exactly two routes: the content itself, or a token credential the host recognizes. Crossing the line rejects the whole call.
Host staging area (decided).The host takes and keeps the content; a plugin no longer keeps its own copy and registers only an address. At send time the host pulls the content from the staging area and it travels as a normal attachment. The staging area follows the session: switching sessions empties it.

Explicit non-goals Settled - includes the S1 red line

  • S1 red line: no path / file:// / URL references. A local path, a file-protocol address, or a network address is never accepted as attachment content. A bare-path attachment rejects the whole call and is recorded in the rejected layer.
  • A plugin never touches another party's attachments. list cannot see other plugins' or the user's entries, and remove cannot touch them.
  • A plugin never keeps an address itself. Content goes into the host staging area, and the old "plugin stores its own copy, registers only a ref" model is retired.
  • No cross-session attachments. The staging area follows the session and is emptied when you switch.
  • Draft text is out of scope. That belongs to render/draft/.
  • There is no "edit attachment". Only add / list / remove; to change content, remove and add again.
