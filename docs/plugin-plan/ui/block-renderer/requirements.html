Block renderer · Requirements

Code blocks inside an AI reply body. A prefix plus a language registration take over rendering of the whole block.

status: finalized - no data-flow page (see "Decisions this round")

Scope Decided

  • It covers only how code blocks inside an AI reply body are displayed.
  • Not covered: the rest of the message body, tool call cards, or a markdown transformer.

Slot shape Decided

Prefix plus language.A language registration must be <pluginId>:lang; existing languages (json / ts / mermaid and any the host highlights) cannot be registered.
  • Whole-block takeover: the header, the copy button, and error messages all belong to the renderer.
  • Any unregistered tag always falls back to the host default code block.

What the plugin gets Decided

  • props = {language, source} - the language tag plus the raw block text
  • The raw text arrives whole and unparsed; its format is a matter between the renderer and the model
  • No host functions and no other data

Explicit non-goals Decided

  • Existing languages cannot be registered (json / ts / mermaid and any the host highlights)
  • No host functions
  • No message context is passed in, and the original message text cannot be rewritten
  • No cross-block coordination and no partial rendering
  • markdown transformer is not provided

Finalized: while streaming, an unclosed fence falls back entirely to the host default code block (showing the raw language string, unhighlighted, copyable); once closed, the plugin block mounts on the next frame via props-once. The block manages its own height, with a single host backstop at 4000px; beyond that it is treated as a render failure (falling back to the host block showing the source).
