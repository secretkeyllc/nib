Tool call card · Requirements

The card shown for each tool call in the conversation. A plugin draws only its own registered tools, and the card displays without interacting.

status: finalized · decisions this round at the end

Scope Decided

  • It covers only how the tool call card is displayed in the transcript.
  • This round is display only: show this call's input and result well.
  • Not covered: tool execution itself, the confirmation and approval above the composer, and the rest of the message body.

Slot shape Decided

No claiming.A plugin draws cards only for tools it registered; host tools and other plugins' tools cannot be customized and always use the host default card.
  • A plugin supplies the card component when it registers the tool, and that card serves calls to that tool only. Registration uses the shared discriminated union { slot:"toolCard", toolName, component }, and toolName must match contributes.agentTools[].name in the manifest.
  • The plugin draws the whole card; there is no partial replacement of, say, only the header or only one half.

What the plugin gets Decided

  • This call's data - tool name, input, status, result
  • The various ids - call id, message id, session id
  • Failure information in the result is data (a field), not a throw
  • No host functions and no extra data surface

Plugin scenarios Decided

ScenarioWith the plugin installed
Its own database query toolThe result renders as SQL plus a table
Its own statistics toolThe result renders as a bar chart
The call failsThe error is data and the plugin renders a failure state

Explicit non-goals Decided

  • No claiming: no customizing host tools or other plugins' tools
  • Display only, no interaction: no next step, approval, confirmation, or retry
  • A plugin may not rewrite the input, intercept, or allow execution
  • A plugin may not start new tool calls
  • markdown transformer is not provided
