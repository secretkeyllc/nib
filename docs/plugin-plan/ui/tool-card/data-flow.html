Tool call card · Data flow

For tools it registered itself, call data is pushed to the card component, and failure is data. Host and third-party tools never reach the plugin.

status: finalized · slot names and props field names are final (see slot-contract.html §6); SDK and host are implemented, example in examples/plugins/ui-slots-lab

1API contract Decided

A plugin supplies the card component when it registers the tool. There is no claiming and there are no host functions. Registration uses the shared discriminated union { slot:"toolCard", toolName, component }, and toolName must match contributes.agentTools[].name in the manifest.

propsMeaning
toolName - toolCallId - messageId - sessionIdThis call and its identifiers (toolName is always a tool this plugin registered)
toolArgs?Input
toolStatusrunning / success / error
toolResult? - toolError? - durationMs?Result / failure information / duration (failure is data, not a throw)

Permission: covered by renderer.extension. Side effects go through the plugin's own plugin.call.

2How data flows Decided

DirectionContent
host → pluginThe whole payload for this call is pushed to the card component; while it runs, pushes are coalesced on a 500ms tick, with state transitions and the final result pushed immediately
plugin → hostNone. No callbacks and no changing execution
Host and third-party toolsThey never reach the plugin and use the host default card

Delivery model: props-push.

3Error handling Decided

CaseResult
Tool execution failsFailure is data, not a throw; it lands in a field and the plugin draws it
A plugin component throwsOnly this card collapses
Plugin not loaded / already unloadedIt falls back to the host default card

4What is not provided Decided

  • No claiming: host and third-party tools cannot be customized
  • No interactive actions (waiting, approval, retry)
  • No host functions and no extra data surface
  • A plugin may not rewrite the input, intercept execution, or start calls

Host guarantees

Failure isolation; registration and injected styles are removed on unload.

Accepted costs

Shares the realm, so globals are reachable; style overrides can be bypassed.
