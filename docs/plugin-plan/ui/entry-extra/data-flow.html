AI reply append area · Data flow

The host pushes this AI reply's data to the append block; the plugin only renders and never calls back into the host.

status: finalized · slot names and props field names are final (see slot-contract.html §6); SDK and host are implemented, example in examples/plugins/ui-slots-lab

1API contract Decided

A plugin registers one append component. It is additive and can stack.

propsMeaning
messageData for this AI reply
messageId / sessionIdvarious ids

Permission: covered by renderer.extension. Side effects go through the plugin's own plugin.call.

2How data flows Decided

DirectionContent
Host → pluginprops are supplied in full up front; the whole set is re-pushed when the message re-renders
Plugin → hostNone
plugin → itselfInteractions are the plugin's own business

Delivery model: props-push. Multiple plugins stack in registration order.

3Error handling Decided

CaseResult
A plugin component throwsOnly its own block collapses
Plugin not loaded / already unloadedThat block disappears and the position is released

4What is not provided Decided

  • No host functions
  • No body editing or whole-card replacement
  • User messages do not get this slot

Host guarantees

Failure isolation; registration and injected styles are removed on unload.

Accepted costs

Shares the realm, so globals are reachable; style overrides can be bypassed.

5Related entries Decided

  • ui/assistant-action/ - the AI reply action bar

6Finalization record Decided

  • The SDK slot name is entryExtra; "AI replies only" is hard-coded in the type: props accept the assistant message variant only and carry no position field
  • A collapsed block is clamped by the host at 320px (with an 8% fade and a host "Expand" button), an expanded block is 600px and scrolls internally, and multiple blocks stack in registration order
