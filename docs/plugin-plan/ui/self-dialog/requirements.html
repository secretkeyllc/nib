Self-managed overlay · Requirements

Full-screen dialogs and corner overlays that a plugin manages itself. No slot and no registration; four hard limits; Esc never closes a security layer.

status: finalized - no data-flow page (see "Decisions this round")

Scope Decided

  • Dialogs (modal) and floating layers (non-blocking) are drawn by the plugin itself.
  • Not covered: the host confirmation card, the host permission approval card, and tool call cards.

Slot shape Decided

No slot, no registration, self-managed. The plugin draws it inside its own component with position: fixed. The host provides no slot, no registration, and nothing to claim.

The four hard limits:

hard limitwhy
Drawn inside its own componentSo it never escapes its style scope
Gone on unloadDisable/unload removes it with the component tree, leaving the host nothing to clean up
Never above a host security layerSecurity layers such as permission approval and confirmation always stay on top
Among plugins, the later-opened sits on topThe host does not arbitrate

What the plugin gets Decided

  • There is no slot, no registration, and no props from the host.
  • A layer appearing and disappearing is just a normal component mounting and unmounting.

Plugin scenarios Decided

ScenarioWith the plugin installed
Full-screen wizardThe plugin draws its own modal dialog
Corner notificationThe plugin draws its own floating layer

Explicit non-goals Decided

  • The host provides no slot, no registration, and no claim arbitration
  • Esc does not close a security layer; closing happens only through an explicit UI action (the close button)
  • A self-managed layer may not stack above a host security layer
