User message action bar · Requirements

Additive positions on both sides of the user message card's action bar. This page records the decided boundaries.

status: finalized · decisions this round at the end

Scope Decided

It covers only the left and right sides of the user message card action bar. It does not touch the message body, AI replies, or tool cards.

Slot shape Decided

Fixed layout: [left slot] host keys [right slot]. The host keys (copy / edit / delete) always sit in the middle, and plugins may only add.
positionmeaning
left slotThe additive area left of the host keys; holds 0..n plugin items
right slotThe additive area right of the host keys; holds 0..n plugin items

What the plugin gets Decided

  • message - the data for this user message (text and so on)
  • the various ids - message id, session id, and similar identifiers
  • position — "left" | "right"
  • No host functions are provided (there are no copy / edit / delete callbacks)
  • No extra data is provided

Plugin scenarios Decided

ScenarioWith the plugin installed
Create ticketOne extra button in the right slot whose click runs the plugin's own logic (the host does not manage it)
StarA status dot in the left slot, with the data stored by the plugin

If a plugin implements delete, forward, or similar capabilities itself, the host does nothing extra (it does not block, does not manage, and provides no functions).

Explicit non-goals Decided

  • No editing, hiding, or removing host keys
  • No changing the message body (the entry body is closed and there is no whole-card replacement)
  • The user card has no entryExtra (only AI replies do)
  • No host functions and no extra data
  • No plugin may override or claim a host key
  • markdown transformer is not provided

Finalized: the SDK slot name is userAction (registered as positions?: ["left","right"]; omitting it means both sides; the props type is the shared PluginActionSlotProps). Each side shows at most three items; the fourth and later move into the host's "..." overflow menu, host keys never collapse, and the layout is recomputed when a plugin is installed or removed.
