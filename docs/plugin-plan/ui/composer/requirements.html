Composer · Requirements

Component slots only: left and right controls, trigger characters, and tokens. Fixed parts belong to the host. Draft read/write and attachment methods live elsewhere.

status: finalized · decisions this round at the end

Scope Decided

  • The plugin position for left and right controls in the composer toolbar.
  • The list that pops up when a trigger character is typed.
  • The tokens inside the composer.
  • Not covered: draft read/write and attachment methods (see render/draft/ and render/attachments/), the send flow, and the internals of the fixed parts.

Slot shape Decided

Fixed parts belong to the host. Attachments, mode switching, permission switching, model selection, and send/stop are out of a plugin's reach. A plugin only contributes component slots.
slotpositionwhat a plugin can do
Left controlRight of the left fixed partsAdd its own button or popover
Right controlLeft of the model selectorAdd its own button
Trigger characterThe list that pops up above the composerRegister one trigger character and supply the list contents
TokenTokens inside the composerHow a selected item looks in the draft

What the plugin gets Decided

  • The component slot's position and rendering environment
  • Trigger character: the filter text; token: the label / send data
  • No control over the fixed parts

Explicit non-goals Decided

  • Fixed parts cannot be hidden, replaced, reordered, or jumped
  • Draft read/write and attachment methods are not in this folder
  • Attachments accept only content|token; path / URL refs are forbidden
  • markdown transformer is not provided

Finalized: the trigger characters are fixed at three - @ / # / / (one character per plugin; a duplicate registration returns PLUGIN_SLOT_DUPLICATE; they fire only at the start of a line or after whitespace and never mid-IME composition, and programmatic writes never fire them). A single draft holds at most eight tokens; from the ninth they collapse into +N, and the send payload loses nothing.
