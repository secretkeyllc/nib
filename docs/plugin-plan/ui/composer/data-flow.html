Composer · Data flow

How data moves through the component slots. Draft read/write and attachment methods live elsewhere.

status: finalized · slot names and props field names are final (see slot-contract.html §6); SDK and host are implemented, example in examples/plugins/ui-slots-lab

1API contract Decided

This folder covers the component slots only: left control, right control, trigger character, and token.

slotwhat the plugin receives
Left / right controlA render position; no extra data
Trigger characterThe filter text the user typed
TokenTwo pieces of data: label and send

Permission: covered by renderer.extension. Draft and attachment methods are in render/draft/ and render/attachments/.

2How data flows Decided

DirectionContent
host → pluginThe trigger filter text; the token render data
plugin → hostTrigger list items; token label / send
plugin → itselfControl interactions are the plugin's own business

3Error handling Decided

CaseResult
A plugin component throwsOnly its own control or list collapses
Plugin not loaded / already unloadedThe slot is released and the fixed parts are unaffected

4What is not provided Decided

  • No control over the fixed parts
  • No draft read/write or attachment methods (they are not here)
  • Attachments accept only content|token; path / URL refs are forbidden

Host guarantees

Failure isolation; registration and injected styles are removed on unload.

Accepted costs

Shares the realm, so globals are reachable; style overrides can be bypassed.

5Related entries Decided

6Finalization record Decided

  • Three fixed trigger characters: @ (context / reference), # (data / resource), and / (commands); full-width forms are normalized; one character per plugin, and a duplicate registration returns PLUGIN_SLOT_DUPLICATE; they fire only at the start of a line or after whitespace, never mid-IME composition, and programmatic writes never fire them
  • A single draft holds at most eight tokens; from the ninth they collapse in place into a host token +N (labelled with the first overflowing plugin); the send payload loses nothing
