1Interface contract

pi.agent.complete(input: PluginCompleteInput): Promise<PluginCompleteResult>

A one-shot model completion dispatched by the host: the plugin supplies its own system prompt and messages, and the host returns text using the user's configured model; permission —, usage counted against the user's model.

Inputs

FieldTypeRequiredDescription
modelKeystringNoTarget model, in the form providerId/modelId; when omitted, the host default / session-bound model is used.
thinkingLevelstringNoThinking level for this request.
systemstringNoCustom system prompt, applies to this completion only.
messagesArray<{ role, content }>NoConversation messages; role is user or assistant.
includeSessionContextbooleanNoWhen set to true, session context is included; the plugin must also hold session.read.
purposestringNoAudit tag, e.g. prompt-enhance.

Outputs

FieldTypeDescription
textstringCompletion text returned by the model.
modelKeystringModel actually used, in the form providerId/modelId.
thinkingLevelstringThinking level actually used.

usage.inputTokensnumberNumber of input tokens.
usage.outputTokensnumberNumber of output tokens.
usage.totalTokensnumberInput + output total.

Input example

{
  "modelKey": "anthropic/claude-sonnet-4-5",
  "system": "你是编辑助手，只输出改写后的句子。",
  "messages": [{ "role": "user", "content": "把这句改得更客气：把文件发我。" }],
  "purpose": "prompt-enhance"
}

{
  "text": "麻烦把文件发我，谢谢。",

Boundary in one sentence.One-shot completion: no tool loop (tools: []), no access to API keys, no implicit writes to session history; use session.getLlmContext to read session content.

2How data flows

  1. Call. The plugin hands PluginCompleteInput to the host at any time.
  2. Validation. The host checks the input and authorization: invalid parameters INVALID_ARGUMENT; not authorized PERMISSION_DENIED; includeSessionContext: true additionally requires session.read.
  3. Limits. system ≤ 32KiB, total context ≤ 200k tokens, 8 calls per 60 seconds, 90-second timeout; over-limit calls are rejected, with no automatic retry.
  4. Execution. The host sends the completion request to the provider with the user's model key — the key never leaves the host and the plugin cannot obtain it.
  5. Return. The plugin receives { text, modelKey, usage }; purpose goes into the audit log, and this call is not written to session history.

4What it does not provide

No access to API keys; no multi-turn tool loop; not a full agent loop.

Host guarantees / accepted costs: Host guarantees: `tools: []` (no tool loop); limits of 32KiB system / 200k tokens / 8 calls per 60 seconds / 90-second timeout. Accepted cost: over-limit calls are rejected, with no automatic retry.
