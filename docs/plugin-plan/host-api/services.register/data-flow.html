1API contract

pi.services.register(service: PluginService): void

Register a resident background service; the id must first be declared in contributes.services. Registration is local and synchronous, and the host decides when to start it. Permission: —.

Input

fieldtyperequirednotes
idstringYesMust match contributes.services[].id; unregister addresses the service by it.
start(ctx: PluginServiceContext) => Promise<void> | voidYesCalled back when the host starts the service; ctx.log(msg) appends a line to the plugin host log.
stop() => Promise<void> | voidNoCalled back when the host stops the service.

Output

fieldtypenotes
(return value)voidReturns synchronously; this only registers locally and does not wait for startup.

Input example

pi.services.register({
  id: "sync-daemon",
  start: async (ctx) => { ctx.log("sync-daemon started"); },
  stop: async () => { /* 释放句柄 */ },
});

Output example

// 无返回值（同步 void）
Boundary in one sentence. Registration is not automatic startup - the host decides when to start; services are subject to backoff supervision, and an abnormal process exit restarts per the manifest's autoRestart (true by default).

2How data flows

  1. The plugin hands over the service object synchronously, and id must already be declared in contributes.services.
  2. Validate: an undeclared id is rejected (INVALID_ARGUMENT), and so is a missing background-service permission (PERMISSION_DENIED).
  3. The host completes local registration and decides when to call start.
  4. On plugin unload or disable the host calls stop first and then clears the registration.
directioncontent
plugin → hostThe service object (id, start, and an optional stop callback).
host → pluginLifecycle callbacks for start / stop (ctx.log writes to the host log).

3Error handling

caseresultcode
The background-service permission is missingThrown synchronously; the registration does not take effectPERMISSION_DENIED

4What is not provided

Local registration is not automatic startup; it is subject to backoff supervision.
