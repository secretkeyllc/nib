1Interface contract

pi.audio.openOutput(options: PluginAudioOpenOutputOptions): Promise<PluginAudioOutputSession>

Opens a playback queue held by the host and returns a playback session (permission: —).

Inputs

FieldTypeRequiredDescription
sampleRatenumberYesTarget playback sample rate.
channelsnumberNoNumber of channels.
format"pcm16"NoSample format; currently only PCM16 is supported.

Outputs

FieldTypeDescription

sampleRatenumberSample rate actually in effect.
channelsnumberNumber of channels actually in effect.
format"pcm16"Playback sample format.

Input example

{ "sampleRate": 24000, "channels": 1, "format": "pcm16" }

Output example

{ "streamId": "out-8c11d0", "sampleRate": 24000, "channels": 1, "format": "pcm16" }
Boundary in one sentence.PCM16 only; you get a queue session, not a device handle — the playback queue is held by the host.

2How data flows

  1. Call: pi.audio.openOutput({ sampleRate, channels?, format? }).
  2. Validation: the host checks the permission (PERMISSION_DENIED if not authorized) and the parameters (INVALID_ARGUMENT if, say, sampleRate is missing).
  3. Execution: the host opens the system playback endpoint, creates a playback queue for this plugin, and holds it.
  4. Return: resolves with the playback session { streamId, sampleRate, channels, format }; audio is enqueued via writeOutput.
  5. Lifecycle: when the plugin is disabled / unloaded, the host discards unplayed audio.
DirectionContent
plugin → hostOpen request (sample rate, channel count, format).
host → pluginPlayback session (streamId and the parameters actually in effect).
host → systemOpens and drives the system playback device.
