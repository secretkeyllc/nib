1API contract

pi.clipboard.getHistory(): Promise<ClipboardHistoryEntry[]>

Read the clipboard history the host retains (permission: —; the history may contain sensitive data, and the permission is clipboard.read).

No input.

Output

Boundary in one sentence. It only reads history inside the host retention window (bounded at 30 days / 500 entries / 256 MiB) and never polls the system clipboard; there is no API to delete history.

2How data flows

  1. Call: the plugin process issues pi.clipboard.getHistory().
  2. Validate: the host checks the read-side permission (clipboard.read).
  3. Execute: the host returns a snapshot of the clipboard history it retains, bounded (30 days / 500 entries / 256 MiB); the host does not poll the operating-system clipboard.
  4. Return: the whole entry array at once, with no cursor and no paging; text and image entries are told apart by type.

4What is not provided

The current surface has no API to delete history.

Host guarantees / accepted costs: Host guarantee: the history is bounded (30 days / 500 entries / 256 MiB) and the OS clipboard is never polled. Accepted cost: older history is unavailable.
