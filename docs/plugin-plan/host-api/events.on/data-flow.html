1API contract

pi.events.on(event: string, handler: (...args: unknown[]) => void): void

Subscribe to a host-pushed event and call the handler when it arrives (permission: —; the binding lasts until events.off or plugin unload).

Input

fieldtyperequirednotes
eventstringYesThe event name; shipped today: bus.message, workspace:changed, plugin:settingsChanged, appearance:changed, session:modelChanged, session:turnEnded.
handler(...args: unknown[]) => voidYesThe handler; the number and meaning of its arguments depend on the event and every argument arrives typed as unknown.

Output

fieldtypenotes
(return value)voidRegisters synchronously and returns immediately with no data; unbind with events.off passing the same function reference.

Input example

pi.events.on("session:turnEnded", (...args) => { turnCount += 1; });

Output example

// no return value
Boundary in one sentence. Subscribe and receive: no receipt and no replay, and events that happened before registration are never resent.

2How data flows

  1. Call: the plugin process passes the event name and a handler.
  2. Validate: subscribing to an unknown event name does not error; the handler simply never fires.
  3. Execute: the host calls the handler when the event fires, spreading arguments as that event defines them (...args: unknown[]); a throwing handler is only logged and never affects the host.
  4. End: when events.off receives the same function reference, or when the plugin unloads.
directioncontent
plugin → hostThe event name plus a handler (subscribe / unbind).
host → pluginThe event arguments (...args: unknown[]), depending on the event type.

3Error handling

No error codes: subscribing to an unknown event name does not error, and it generally does not fail.

4What is not provided

No receipt and no replay.
