1API contract

pi.desktop.invoke(input: PluginDesktopInvokeInput): Promise<unknown>

Asks the host to perform a desktop operation from the reviewed catalog on the plugin's behalf (the same catalog as the local MCP control plane); permission —.

Input

Boundary in one sentence. Allowlisted proxy: executes only operations in the reviewed catalog, exposes no arbitrary IPC; the audit records only the operation id and result, argument values never enter the audit body.

2How data flows

  1. Call. The plugin requests execution by operation id and positional arguments (the catalog can be fetched first via desktop.listOperations).
  2. Validate. The host looks the operation up in the reviewed catalog: unknown name NOT_FOUND, mismatched arguments INVALID_ARGUMENT, unauthorized PERMISSION_DENIED.
  3. Confirm. dangerous operations need double confirmation: the plugin sets confirm: true and the user answers in a native dialog; the dialog names the operation id and shows no text written by the plugin or model; missing confirmation returns CONFIRMATION_REQUIRED.
  4. Execute. The host performs the operation on the plugin's behalf and returns the result to the plugin.
  5. Audit. The post-hoc audit records only the operation id and result; argument values never enter the audit body.

plugin → hostOperation id, positional arguments, plugin confirmation flag.

host → pluginOperation result (shape varies by operation).

4What is not provided

No arbitrary IPC; argument values never enter the audit body.

Host guarantee / accepted cost: Host guarantee: a prompt-injected transcript cannot rewrite a dangerous operation into harmless-looking text. Accepted cost: argument values are not audited, so afterwards only the operation id and result are visible.
