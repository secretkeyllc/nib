1API contract

pi.session.list(input?: { limit?: number; cursor?: string; source?: string; updatedAfter?: string }): Promise<PluginSessionListResult>

List imported session metadata for this plugin, isolated by source. Permission: —.

Input

fieldtyperequirednotes
limitnumberNoThe per-page item cap.
cursorstringNoThe nextCursor from the previous page, used to fetch the next one.
sourcestringNoFilter by source namespace; only a sessionSources entry this plugin declared is allowed.
updatedAfterstringNoReturn only sessions updated after that instant.

Output

fieldtypenotes
itemsPluginSessionListItem[]The sessions on this page. Each element carries sessionId, title, source, externalId, projectId (number|null), messageCount, originKind ("imported"|"created"), bound.workspace, bound.model, createdAt, and updatedAt.
nextCursorstringPresent when another page exists; pass it back as cursor to continue, otherwise absent.

Input example

{ "limit": 20, "source": "wechat-export" }

Boundary in one sentence. It can only list sessions owned by this plugin's source; host-created sessions and other plugins' sessions are invisible.

2How data flows

  1. Call: the plugin may pass limit / cursor / source / updatedAfter.
  2. Validate: rejected when the session.read.own permission is missing or source is not declared in the manifest.
  3. Execute: the host filters by this plugin's source and reads session rows page by page.
  4. Return: items plus nextCursor; loop on the cursor until it is absent.
directioncontent
plugin → hostThe filter and paging parameters (limit / cursor / source / updatedAfter).
host → pluginA page of session metadata, { items, nextCursor? }.

3Error handling

caseresultcode
No session.read.own, or source is undeclaredCall failed; no data returnedPERMISSION_DENIED

4What is not provided

Cannot list another plugin's sessions.

Host guarantees / accepted costs: Host guarantee: nothing is visible across plugins. Accepted cost: host-created sessions are not visible.
