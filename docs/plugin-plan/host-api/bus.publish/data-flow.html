1API contract

pi.bus.publish(topic: string, payload?: unknown): Promise<void>

Publishes one message to a declared topic, broadcast to other subscribing plugins (permission: —; the topic must match a declaration in the manifest contributes.bus.publish).

Input

FieldTypeRequiredNotes
topicstringYesConcrete topic, no wildcards: dot-separated segments, each matching [a-zA-Z0-9][a-zA-Z0-9_-]*; at most 8 segments and ≤128 characters in total.
payloadunknownNoMessage payload; semantics are defined by the publisher; omit it for no payload.

Output

FieldTypeNotes
(return value)voidNo return data; resolves on publish, with no delivery receipt.

Input example

pi.bus.publish("notes.index.ready", { count: 42 })

Output example

// void - resolves as soon as the message is published, no output
Boundary in one sentence. Fire-and-forget: no persistence and no delivery guarantee; fan-out excludes the publisher itself.

2How data flows

  1. Call: the plugin process passes a topic and an optional payload.
  2. Validate: topic must be a valid concrete topic (segment rules, ≤8 segments, ≤128 characters, no wildcards) and must match a declaration in the manifest contributes.bus.publish; otherwise PERMISSION_DENIED.
  3. Execute: the host stamps the message with from (the publisher's plugin id) and at (an ISO timestamp assigned by the host), then fans out to subscribers' topic patterns; the publisher's own subscriptions are not among the recipients.
  4. Return: no receipt value; subscribers receive a PluginBusMessage.
DirectionContent
plugin → hosttopic + payload.
host → pluginPluginBusMessage (topic / from / payload? / at) dispatched to the matching subscriber plugins.
