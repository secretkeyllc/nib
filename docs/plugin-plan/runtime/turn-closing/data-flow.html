The path of the end-of-turn query and the continuation, and where the attribution gap sits. Six fixed sections: API contract / How data flows / Error handling / What is not provided / Related entries / Open questions.

status: draft · issue #561 · permission runtime.turn.closing · continuation goes through agent.steer · plugin attribution missing (defect)

1API contract Proposal

A headless hook, runtime.turn.closing. A passive query at turn end.

// end of turn: the host asks whether to continue
pi.on("turn_closing", async () => {
  if (needMore()) return { continue: true, message: "还有两项未完成，请继续" };
  return { continue: false };
});
// continuation: injected via agent.steer({ role: "user" }) - no plugin attribution (defect)

Life of one continuation

momentwhat happens
Before closingThe host issues the end-of-turn query
PluginSuggests continuing (optionally with a message) or not
ArbitrationWith several plugins, the first continue wins
Continuationagent.steer({ role: "user" }) injects the message and runs the next turn - that message has no plugin attribution (defect)
Compareturn-continue → queuePush adds pluginId / pluginLabel
The continuation path lacks attribution. What steer injects is an anonymous user message; the user cannot tell that a plugin suggested continuing. The one with attribution is runtime/turn-continue/'s queuePush. The documents are cross-references for each other.
