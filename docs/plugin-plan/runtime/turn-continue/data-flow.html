turn-continue · Data flow

The path of a message from the plugin to the host queue, and then into an attributed continuation turn. Six fixed sections: API contract / How data flows / Error handling / What is not provided / Related entries / Open questions.

status: draft · issue #561 · permission runtime.turn.continue · goes through queuePush · plugin attribution visible

1API contract Proposal

A headless interface, runtime.turn.continue. It returns as soon as the message is queued, without waiting for the work to finish. It carries plugin attribution.

// queue a continuation message attributed to the plugin
const r = await pi.continueTurn({ message: "继续处理剩下的文件" });
// a queued row with the plugin attribution appears in the conversation; turns run in queue order

The split from turn-closing. This path (queuePush) carries attribution; turn-closing's continuation goes through agent.steer({role:"user"}) with no plugin attribution - that is a defect, see runtime/turn-closing/.
