1API contract

pi.session.getContext(input?: { sessionId?: string; scope?: "all" | "sinceCompaction"; maxCharsPerMessage?: number }): Promise<PluginSessionContext>

Reads the full context working set of the current session. Permission session.context.read (new · high · confirmed at install - it can read message bodies).

Input

FieldTypeRequiredNotes
sessionIdstringNoDefaults to the current session; reading across sessions must be explicit (same permission).
scope"all" | "sinceCompaction"NoDefaults to sinceCompaction: returns only the working set since the last compaction; "all" returns everything.
maxCharsPerMessagenumberNoTruncation limit per message body; defaults to the host default. When truncation happens that message has contentTruncated = true.

Output

FieldTypeNotes
sessionIdstringThe session id the snapshot belongs to.
compactionCursorstring | nullId of the latest compaction record; used for the concurrent check in applyCompaction (CONFLICT detection).
systemstring | undefinedThe current system prompt; absent when there is none.
messagesArray<{…}>Array of messages; the element shape is described below.
messages[].idstringMessage id.
messages[].role"user" | "assistant" | "tool"Role; system is returned separately in the system field.
messages[].contentstringThe body; when truncated for budget reasons contentTruncated = true.
messages[].contentTruncatedboolean | undefinedWhether this message was truncated.
messages[].createdAtstringISO timestamp string, consistent with session.listMessages.
messages[].tool{…} | undefinedMetadata for a tool message: name / callId / status("success"|"error") / resultPreview (preview only, never the full text).

Boundary in one sentence.It can read message bodies, so its permission is broader than session.read; tool results expose only resultPreview, never the full text. Prerequisite: the implementation must lift the current "callable only during tool execution" restriction on session.getLlmContext and switch to pure permission gating - compaction happens at the turn boundary, not inside any tool call.

2How data flows

  1. Call. The plugin passes the optional { sessionId?, scope?, maxCharsPerMessage? }.
  2. Validate. The main process checks the session.context.read permission (a high-sensitivity domain confirmed at install) and resolves the target session.
  3. Assemble. The host reads all session messages and the latest compaction record from the same chain used by session.getLlmContext, then trims by scope: rows before the compaction point fold into the summary context; tool results are reduced to resultPreview; and content is truncated by the overall budget and the per-message limit.
  4. Return. Everything at once; no subscription and no streaming. Going over budget is not an error and is reported honestly through estimate.truncated.
directioncontent
plugin → hostThe read description (scope, per-message truncation limit, target session).
host → pluginThe context snapshot (system + messages + estimate + compaction position).
