tool-extend · Data flow

The path of the three return-value fields from the plugin to the host. Six fixed sections: API contract / How data flows / Error handling / What is not provided / Related entries / Open questions.

status: draft · issue #561 · permission runtime.tool.extend · addedToolNames / usage / terminate

1API contract Proposal

Not a call, but three optional fields on the return value of a plugin's own tool; the host decides by runtime.tool.extend authorization whether to accept or strip them.

// a plugin-owned tool's return value (illustrative)
return {
  ...normalResult,
  addedToolNames: ["my-next-step"],
  usage: { costUsd: 0.02 },
  terminate: true,
};
aspectcontent
addedToolNamesIntroduces new tools; attributed to the plugin in the UI; no authorization → stripped plus an audit record
usageReports cost; no authorization → stripped plus an audit record
terminateRequests a batch termination; no authorization → stripped plus an audit record
Permissionruntime.tool.extend; refusals / stripping are both audited
