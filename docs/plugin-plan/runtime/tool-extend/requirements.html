tool-extend · Requirements

The return value of a plugin's own tool may carry three optional fields. The host decides, by permission, whether to accept or strip them.

status: draft · issue #561 · permission runtime.tool.extend · addedToolNames / usage / terminate

Scope Verified

  • Covers only the three optional fields on the return value of a plugin's own tool.
  • Out of scope: intercepting the host's built-in tools (tool-gate), the send path (before-send).

Current state (code-verified) Verified

  • The three fields are already in the contract: addedToolNames / usage / terminate, accepted or stripped according to runtime.tool.extend.

  • Not authorized → stripped plus an audit record - not a silent drop, and not a failure of the whole result.

An introduced tool is attributed to the plugin author. Users can see in the UI who added the tool; it is subject to permission gating.

Explicit non-goals Verified

  • An unauthorized plugin may not use these three fields to escalate privileges - without permission they are stripped.
  • addedToolNames may not register a tool with the same name as a built-in one (overriding the host).
  • It does not change the result of a host tool - that is tool-gate's read-only boundary.
  • terminate is not the whole-turn abort semantics of abort-turn (different scope).
