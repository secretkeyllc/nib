2How data flows Verified

There is no data to flow. The table below is the scenario migration - where each place that once wanted to modify the request goes now.

what was wanted from before-requestwhere it goes now
prompt injection / assemblyinject / compose (session prompt assembly)
History governance (trimming, summarising, ordering)Host compaction; plugins do not rewrite the request body
model / think overrideSession binding (the model and thinking level bound to the session)
Outbound content interception / rewritingbefore-send (the send path, with auditing)
Cancel this requestabort-turn (abort the current turn)
Outbound interception goes through before-send, not here. before-send has three actions and diff-level auditing; request-layer rewriting is withdrawn.

3Error handling Verified

Since it is not exposed, there are no paths for "plugin throws / timeout / rewrite persisted". The runner rejects the event and records a diagnostic, so an old plugin cannot silently stop working without knowing it.
