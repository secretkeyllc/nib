before-send · Index

The moment when a user message is already persisted but has not yet reached the agent. A plugin can let it through, rewrite the text, or block this send with a reason. Runtime hooks are called headlessly on the agent side, so this folder has no demo page.

Summary

  • Current state verified: the core already emits this hook - "already emitted", not "not emitted".
  • Three actions: continue lets it through / transform rewrites it (with new text) / handled blocks it (with a user-readable reason). Multiple plugins are chained in registration order, and each rewrite is audited individually.
  • Rewrites are audited: every transform is recorded in plugin_rewrites (diff-level); the user message row in the conversation always keeps the original text.
  • Not handled: attachments, the already-persisted user message row, the send button and queueing (those belong to the composer). No state checks such as "return false when no turn is running" - not verified, so not written into the contract.

Open questions

Who can use it, the shape of the user-facing handled notice, the budget duration, and rewrite visibility - see "Decisions this round" in requirements.html.
