before-send · Requirements

The single interception point on the send path: the user message is persisted but has not reached the agent. A plugin can let it through (continue), rewrite it (transform), or block it (handled). Rewrites must be audited.

status: draft · issue #561 · permission runtime.send.before · risk high · three actions continue / transform / handled

Scope Verified

  • Covers only one moment on the rpc send path: the user message is persisted but has not entered the agent loop.
  • Not covered: the send button and queue notices (the composer's job), model request rewriting (before-request, withdrawn), and approval cards.

Current state (code-verified) Verified

  • Already emitting: the agent runtime calls extensionBeforeSend on the send path, event name input, permission runtime.send.before.
    feat/528-plugin-slots@ · packages/agent-runtime/src/runtime.ts · extensionBeforeSend
    feat/528-plugin-slots@ · packages/shared/src/trusted-extensions.ts · SEND_BEFORE / runtime.send.before
  • Three actions: continue / transform / handled. handled throws pluginHandledPromptError, this send does not reach the agent, and the reason is shown to the user verbatim.
  • Rewrites are audited: each transform is recorded in plugin_rewrites (diff-level); the user message row keeps the original text.
    feat/528-plugin-slots@ · packages/agent-runtime/src/runtime.ts · the plugin_rewrites write
  • Trust tier: risk high, confirmed separately when the plugin is installed; a refusal is reported as permission_denied, never silently.
  • No state checks: the contract has no "no turn running → false" - not verified, so not invented.
  • Sandbox plugins cannot reach it yet: the wiring channel for sandbox plugins (ADR 0300) does not exist yet - registration, budgets, and circuit breakers are all missing.
The dispatch mechanism already exists. The trusted-extension runner gates on permission uniformly, rejects withdrawn events, and treats a timeout as no opinion (continue), so a send never hangs.

Explicit non-goals Verified

  • Plugins cannot modify attachments (images / attachments are read-only).
  • Plugins cannot modify the already-persisted user message row - the original is kept, and a rewrite only affects the text that reaches the agent, with an audit trail.
  • No send queueing or withdrawal - that belongs to the composer and the queue.
  • No state checks such as "no turn running → false" (not verified).
  • No touching tool arguments (the same bottom line as tool-gate: argument rewriting is permanently excluded).
