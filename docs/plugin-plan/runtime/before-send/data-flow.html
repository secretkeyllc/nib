before-send · Data flow

What happens at the moment the plugin is called, after the user presses send and before the message reaches the agent. Six fixed sections: API contract / How data flows / Error handling / What is not provided / Related entries / Open questions.

status: draft · issue #561 · permission runtime.send.before · risk high · three actions continue / transform / handled

1API contract Proposal

A headless hook: the plugin registers a listener on the agent side; permission runtime.send.before, risk high, confirmed at install time.

// 插件 headless 入口注册（建议形态）
pi.on("input", async (payload) => {
  // payload: { sessionId, turnId, text, images, attachments, source: "rpc" }
  if (await hasSecret(payload.text)) {
    return { action: "handled", reason: "检测到疑似密钥，已拦下这次发送" };
  }
  return { action: "continue" };
})

Life of a send

momentwhat happens
PersistedThe user message row is stored first (the original)
HookRegistered plugins are called in order
Along the chainEach plugin picks one of three; a transform feeds the next plugin and is audited
Someone handles itThe send is blocked, the reason is shown to the user, and the chain stops
All passed / rewrittenThe final text is handed to the agent and the turn begins
The original and the text that reaches the agent are two separate things. What the conversation displays, stores, and refills when editing is the original; a rewrite only affects the copy handed to the model, and every one is auditable.
