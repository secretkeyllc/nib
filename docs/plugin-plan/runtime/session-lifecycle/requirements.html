session-lifecycle · Requirements

The five moments of a session lifecycle. Only the pre-compaction point (before_compact) can veto; everything else is a notification.

status: draft · issue #561 · permission runtime.session.lifecycle · only before_compact can veto

Scope Verified

  • Only session-level moments: create, delete, switch, fork, compaction.
  • Out of scope: in-turn events (turn-watch), reading and writing messages (turn-recap / other interfaces).

Current state (code-verified) Verified

  • The slot is registered and gated: runtime.session.lifecycle.
    feat/528-plugin-slots@ · packages/shared/src/trusted-extensions.ts · runtime.session.lifecycle
  • Events come from three places: create / delete are emitted by the desktop, switch / fork are forwarded by the desktop, compact is emitted by the sidecar itself.
    feat/528-plugin-slots@ · apps/desktop/electron/ipc/session-ipc.ts · session lifecycle emit
    feat/528-plugin-slots@ · packages/agent-runtime/src/runtime.ts · session_compact / session_before_compact
  • before_compact payload (write it exactly like this): { type, reason, retentionMode, segment: { messages, messageCount, tokensBefore, retained } }; it may return { cancel?: boolean }; only a compaction can be vetoed.
  • Notifications do not wait by default: everything except before_compact is notification-style - it does not wait for the plugin and cannot be blocked.
  • Sandbox gap: the wiring channel for sandbox plugins (ADR 0300) does not exist yet - registration, budgets, and circuit breakers are all missing.
The veto is granted to compaction only. Switching a session, forking and deleting are direct user actions - a plugin is told about them but cannot block them. Compaction is an automatic background behaviour, so plugins get one chance to say "not yet, I still need to read this".

Explicit non-goals Verified

  • Plugins may not veto switch / fork / delete - direct user actions cannot be blocked.
  • Notification events may not make the host wait for a plugin - everything except before_compact is notification-style.
  • Plugins may not rewrite the compacted segment's content - they can only cancel this one compaction, not change messages.
  • Plugins may not change the retention policy itself - retentionMode is read-only.
